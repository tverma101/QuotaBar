# Windows port plan

**Goal:** retain all behavior in the [macOS feature and screen inventory](FEATURES.md) and [provider inventory](PROVIDERS.md), including the look and motion of app-owned surfaces. The original plan did not account for the existing port; this revision starts from [`windows/`](../../windows) on main at `9141aa3` and scopes only the remaining gaps. It is not a claim of parity.

## Stack and feasibility decision

**Extend the existing Tauri 2 + React/TypeScript + Rust app, using WebView2 and targeted Win32 changes.** Reuse the shell in [`src-tauri/`](../../windows/src-tauri), the screens/hooks/stores in [`src/`](../../windows/src), the Windows Rust core and CLI in [`crates/`](../../windows/crates), the JS provider plugins in [`plugins/`](../../windows/plugins), and the [local API](../../windows/src-tauri/src/local_http_api). Keep credential and filesystem work in native/plugin-host paths, not UI storage. Swift providers implement `ProviderRuntime`; Windows probes are JS plugins executing against the Rust host plus native history/scanner helpers. Match inputs, normalized outputs, identity and failure semantics with fixtures; do not transplant provider architecture. The separate macOS [Rust core](../rust-core.md) is not the Windows workspace.

CSS/SVG/canvas let the existing React UI control app-owned geometry and produce deterministic share fixtures. WinUI or native Direct2D would replace working screens without solving Explorer or capture constraints; Windows Swift cannot reuse SwiftUI/AppKit. Use native changes where WebView2 cannot deliver the required focus, DPI, capture/privacy or lifecycle behavior, and verify those at runtime.

**Tray limitation:** Explorer notification icons are fixed-size square slots; Windows offers no supported arbitrary-width menu-bar item. The port should ship one normal QuotaBar tray icon (tooltip and click to toggle) **plus an opt-in app-owned contiguous strip** anchored to the taskbar/notification area, with the identical text/bars layout, light/dark tint, pins, snooze, countdowns and wordmark privacy behavior. Prototype an owned top-level window (not injected into Explorer); use tray icon rect when available, fall back to monitor working area, avoid stealing focus or covering other apps/fullscreen surfaces. Account for overflow, auto-hide, Explorer restart, taskbar placement and multiple monitors. Do not represent the square icon alone as the strip. Absolute OS-pixel identity of Explorer vs the macOS status bar is not possible; release requires approval of this shell equivalence, or the requirement remains unmet.

## Compute efficiency on Windows

These are **proposed release budgets**, not measurements or a reason to reduce behavior. Gate on signed release builds on Windows 11 x64 (four physical cores, 8 GiB RAM, SSD, fixed WebView2 version); exercise AC, battery saver and mixed DPI. Use local synthetic histories and recorded provider responses, plus an authorized live-network smoke test. Compare against an app-off trace, record the build, hardware, provider count, power mode and WebView2 version, and count the QuotaBar process **and its dedicated WebView2 browser/renderer/GPU/utility and scan-worker descendants**. Report CPU as a share of **one logical core**, not a percentage diluted across the machine.

| Area | Release budget | Windows measurement |
|---|---|---|
| Tray-only idle and memory | Across 30 min steady state, excluding tagged refresh/user work: mean CPU ≤0.25% of one logical core and p95 of one-minute windows ≤0.5%. **Implementation order.** Move the recurring refresh deadline out of `src/hooks/app/use-probe-auto-update.ts` before suspending the hidden webview: Rust keeps tray state, scheduling, refresh and notifications alive without JS. Use the actual HWND visibility lifecycle, not DOM visibility alone; `use-now-ticker.ts` already pauses on `document.hidden`, and `panel_windows.rs` already blocks its 250 ms blur watcher while hidden. Evaluate WebView2 `TrySuspend`/`Resume` on the owning thread; fall back to no recurring JS work when suspension is unavailable or fails. Replace polling only if focus/owned-popup behavior holds. For scanner work, extend Windows `quotabar-core`: the current Claude/Codex scanners reuse entries by file size/mtime but reparse the changed file. Keep file identity, last complete offset, bounded incomplete tail and compact aggregate checkpoints in Rust; allow full rereads when replacement/mutation invalidates state. Do not treat cached raw-entry vectors as incremental tail parsing.

**Development baseline (Windows Server 2022 VM, 8 logical CPUs).** With the existing debug app and Vite running, PowerShell sampled cumulative CPU time and memory at both ends of two ~60 s no-input windows. It included QuotaBar and six stable WebView2 descendants, excluded the Vite/Cargo processes, and checked the main HWND was hidden at both hidden-sample endpoints.

| Window | Elapsed | Mean % of one logical core | Aggregate working set at endpoints | Aggregate private bytes at endpoints |

| Panel left open | 60.19 s | 1.272% | 385.12 → 376.83 MiB | 169.03 → 150.30 MiB |

## How to verify

1. **macOS required, not done:** Run the reference at the pinned SHA on macOS 15 and 26. Existing reference commands: `bash script/build_rust_core.sh`, `swift test --filter ReviewScreenshotTests`, `swift test --filter HistoryDashboardViewSnapshotTests`, and the CI suite `bash script/test_suites.sh`. Use the existing [review PNGs](../../.github/review) as starting points, not proof of coverage. Freeze reference clock, locale/time zone, locale-specific currency and sample snapshots; use synthetic accounts, record 1× and 2× in light/dark, both densities, reduced motion/contrast/transparency, and capture shell context independently from app pixels.
2. **Compare app-owned pixels:** Pair PNGs with the same content/viewport/color space. Compare layout bounds, vector geometry, icon alpha masks, colors and text baselines first, then generate image diffs at matched DPI; require exact geometry and matching flat colors, review any antialiasing/font/backdrop deviations on named masks rather than applying a blanket similarity threshold. Keep dashboard, History, Customize pages, Settings, trays, menus/hover, dialogs, loading/error states and share cards in the matrix. Compare keyframes and final geometry of resize/slide/drag/spring with matching timestamps; confirm reduced-motion variants settle without decorative work. OS-owned chrome diffs must be explicit approvals, not automatically masked passes.
3. **Windows Server 2022 today:** Build/test and headless checks apply to the existing workspace; an interactive desktop with WebView2 can exercise app-owned windows. Server is not a stand-in for Windows 11 Explorer behavior, graphics/capture, notifications or store/installer policy. Validate on supported desktop Windows releases, 100/125/150/200% DPI and mixed-monitor/restart/auto-hide scenarios, plus native vendor tools. Establish the minimum supported Windows client version before packaging; test Windows on ARM only if advertised.
4. **Release gate:** Track each inventory row as equivalent, approved OS equivalent, or blocked, with fixture/live and screenshot evidence. Don't count prospective paths, screenshot-only tests or a successful build as verified integration. Do not ship as 100% while any supported provider source, privacy behavior or app-owned visual state is unverified.

## Decisions and risks

- **Release-blocking:** confirm that an app-owned status strip is the accepted equivalent, and agree on automatic screen-share privacy behavior. Explorer cannot draw the macOS strip and Windows cannot universally sense other apps' sharing.
- **Release-blocking:** prove authorized access to Claude Desktop, Cursor, Antigravity, Freebuff and other OS credential sources on native Windows versions. Private endpoints/schemas can change; unsupported tool or credential type is not equivalent to “not logged in.” Test without storing provider tokens in logs/fixtures.
- **Reference/license:** do not ship Apple system fonts/SF Symbols without rights. Use approved substitute glyphs/fonts and document remaining raster/glyph differences. Glass/material and force feedback cannot be assumed on all OS/device combinations.
- **Cross-process and date correctness:** file rotation/locking/reparse behavior, same-file accounting, locale/clock, WSL coexistence and path precedence can change totals or leak account history if ported naively. Use synthetic Windows and cross-platform fixtures before live checks.
- **Sync, updates and install:** current fork has no working default iCloud or updater. A new active service, feed or signing policy is a separate product decision; preserve disabled and unavailable behavior without promising either. Confirm Windows signing, startup trust, WebView2 availability and installer format up front.
