# Windows parity gap matrix

**Baseline:** [main at `9141aa3`](https://github.com/tverma101/QuotaBar/tree/9141aa3/windows), including the Windows app merged in PR #50. Comparison target: [macOS feature inventory](FEATURES.md) and [macOS provider inventory](PROVIDERS.md). Paths in the tables are relative to [`windows/`](../../windows). This is code inspection, not evidence of live provider, visual or end-to-end parity.

**Done** = counterpart wired with no material functional gap identified for that row (still needs applicable release QA). **Partial** = counterpart exists but subfeatures or contracts differ. **Missing** = no corresponding wired feature found. **Divergent** = deliberate or material replacement with a different product behavior/UX, not a claim that the Windows implementation is broken. Count one status per row, not per control or per provider capability.

## Preserve Windows-only work

The tree contains 30 plugin manifests (including separate Antigravity and Cursor variants), Classic/Modern layouts, localized controls, a tray readout, CSV/history exports, TUI/daemon, Start Hidden, support bundle and per-user NSIS delivery. These have no blanket requirement to match macOS. Keep existing preferences and integrations working; add a parity UX without silently removing these capabilities. See [Windows README](../../windows/README.md), [provenance](../../windows/PROVENANCE.md), `src/components/{app/app-shell,app/modern-shell,tray-readout-dialog}.tsx`, `crates/quotabar-cli/src/{tui,daemon.rs}` and [release instructions](../releasing.md).
